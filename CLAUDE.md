# CLAUDE.md

## Project Overview

FocusLens has two distinct products sharing one repo:

1. **Desktop + extension tracker** — privacy-first, local-only. A Python tray
   agent records active-window time on Windows; a Chrome MV3 extension adds
   per-domain browser time. Everything aggregates into one local SQLite database
   served by a loopback Flask server with an HTML dashboard — no cloud, no
   accounts. Remote access is an opt-in Cloudflare quick tunnel.

2. **Android consumer app** — standalone premium screen-time blocker. An
   always-on Kotlin foreground service (`FocusBlockerService`) blocks apps after
   configurable daily limits and during manual focus sessions. Onboarding, a
   RevenueCat paywall, and Sentry crash reporting are already integrated.
   Optionally syncs usage to the desktop agent over LAN.

## Tech Stack

- Desktop agent: Python 3 — Flask, pystray, pywin32, psutil, SQLite (WAL)
- Dashboard: vanilla HTML/CSS/JS, single files (no framework, no build step)
- Browser extension: Chrome MV3, TypeScript, Vite, Vitest (pnpm workspace)
- Mobile: Expo / React Native (Android only), npm; custom Kotlin native module
  (foreground service, overlay activity, installed-app icons/list);
  RevenueCat (`react-native-purchases` v10 + `react-native-purchases-ui` v10);
  Sentry (`@sentry/react-native`); `expo-linear-gradient` (mint CTAs/orb),
  `@expo/vector-icons` (Ionicons — font embedded via `expo-font` plugin so it
  renders in release builds), `expo-notifications` (streak/session reminders),
  `expo-splash-screen` (dark orb splash). App icon is the mint "lens orb",
  generated by `scripts/gen-icon.js` (pure-Node PNG, no image deps).
  Dark "Opal-style" mint palette in `src/theme.ts` — see Code Style.
- Packaging: PyInstaller (`focuslens.spec`); remote access via `cloudflared`
- Hosting: Netlify, static only, publishes `website/`

## Build, Dev & Test Commands

```bash
# Desktop agent (primary component)
cd apps/desktop
python -m pip install -r requirements.txt
python run.py                  # tray + dashboard at http://127.0.0.1:48732/
python -m pytest tests/ -q     # 62 tests

# Extension + shared TS (pnpm workspace, run from repo root)
pnpm install
pnpm test                      # Vitest: packages/shared + apps/extension
pnpm build:extension           # outputs apps/extension/dist — load unpacked

# Mobile (npm, NOT pnpm)
cd apps/mobile
npm install
npx tsc --noEmit               # typecheck — the standard check after edits
npx expo run:android           # user tests locally over USB/wireless adb
# Do NOT run `eas build` after every change — the user builds locally via
# `expo run:android` (compiles the native Kotlin module too). EAS only on request.

# Windows .exe
cd apps/desktop && pyinstaller focuslens.spec --noconfirm
```

No linter is configured in any package.

A `Stop` hook (`.claude/hooks/stop_check.py`, wired in `.claude/settings.json`)
runs automatically at the end of each Claude Code turn: scans changed/untracked
files for hardcoded-secret patterns, runs `apps/mobile` `tsc --noEmit` if any
mobile `.ts`/`.tsx` changed, and `apps/desktop` `pytest` if any desktop `.py`
changed. It blocks the turn from ending on failure. Fails open (never blocks)
if git or the checks themselves error out unexpectedly.

Desktop data flow: sources POST minute buckets to Flask `/events`; dashboard
reads `/api/summary`. Desktop writes accumulate (`upsert_usage`); Android
snapshots replace (`replace_usage`, midnight bucket) so repeated syncs
never double-count.

Android blocking flow: `FocusBlockerService` ticks every second, reads the
foreground app via `UsageStatsManager`, and blocks via `BlockActivity` when any
of four things fires: an active **focus session** (until deadline), an active
**Schedule** rule (day/time window, `ScheduleStore`), an **Open Limit** rule
(opens/day or minutes-per-open exceeded, `OpenLimitTracker`), or a **daily time
limit** (`LimitStore`, checked every 30 s). Apps in the global **Always Allowed**
whitelist (`AllowStore`, `fl_allowed`) short-circuit before any check — never
blocked. Both Schedule and Limit blocks offer a once-daily "break"/joker unless
the rule is `strict` (Hard mode, Pro). Block count in `BlockStats` gates the
free tier (3 events → paywall).

Usage counting (`UsageHelper.usageSinceMs`): single-foreground model — a
RESUMED for app X implicitly closes the previous app's interval, so remote/
overlay apps (AnyDesk) that fire RESUMED without a matching PAUSED can't run
away. Deliberately does NOT gate on screen on/off, so genuinely-foreground apps
during screen-off (remote control, casting) are counted — this matches Android
Digital Wellbeing. Display rounds to the nearest minute (Wellbeing rounds).

Gamification & retention (all local): a **Focus Score** (`score.ts`, clamped
1–99 — never a trivial 100) is a weighted composite: focus sub 60% (screen-time
curve, −6/h), distraction sub 25% (share of time in social/video/game apps via
`isDistractingPkg`), discipline sub 15% (limits respected), plus a +4/session
redemption bonus. A **streak** counts "good days" — a completed focus session
OR a day that ended with score ≥ 65 and real usage data (`streaks.ts`),
surfaced as a flame chip + Gemstones grid (`ProfileScreen`). Local
**notifications** (`notifications.ts`) fire on session-end, an evening
streak-at-risk reminder, and gem unlocks.

## Data Model

SQLite at `%LOCALAPPDATA%/FocusLens/focuslens.db`, schema in `store.py`:

- `usage_minutes(bucket_ts, source, kind, key, label, active_secs, idle_secs)`
  — PK `(bucket_ts, source, kind, key)` WITHOUT ROWID. source: desktop |
  extension | android; kind: app | domain. bucket_ts is unix, minute-aligned.
- `limits(id, target_kind, target_key, period, limit_secs, limit_type, enabled)`
- `reminder_log(limit_id, date, threshold_pct)` — dedups limit notifications
- `settings(key, value)` — pairing_token, retention_days, idle_threshold_secs

Android-local state (no SQLite; the service has no JS bridge):
- SharedPreferences `fl_limits` — daily caps + joker windows (`LimitStore`)
- SharedPreferences `fl_schedules` — Schedule + Open-Limit rules, one JSON blob
  per rule keyed by id (`ScheduleStore`; fields: type, packageNames, daysOfWeek,
  start/endMinute, maxOpens, perOpenSeconds, strict, enabled)
- SharedPreferences `fl_open_limits` — per-rule/app opens-today + reset grant
- SharedPreferences `fl_allowed` — Always-Allowed whitelist (StringSet)
- SharedPreferences `fl_block_stats` — lifetime + per-day block counters
- AsyncStorage (JS): `fl_onboarded`, `fl_name`, `fl_block_rules`,
  `fl_limit_labels`, `fl_streak`, `fl_focus_totals`, `fl_sessions_today`,
  `fl_pending_session`, `fl_gems_seen`, `fl_score_history`

## Code Style & Conventions

- Dashboard/website HTML files are intentionally self-contained (inline CSS/JS,
  Google Fonts + qrcodejs via CDN). Do not introduce a bundler for them.
- Design tokens: **dark "Opal-style" mint palette across the whole product** —
  bg `#070A08`, surfaces `#141A16`/`#1E2521`, ink `#F2F6F3`, mint accent
  `#A9EEC8` with dark text on it (`--on-accent`/`onAccent` `#08130C`), flame
  `#F5B96B`, red `#F08573`. Desktop dashboard + `mobile.html` use CSS vars in
  `:root` (the `--amber` var is now the mint accent — name kept for churn-free
  diffs); the mobile app mirrors the same values in `src/theme.ts` as `C.*`.
  The old warm cream palette is fully retired. Fonts unchanged: Fraunces
  (display numbers), DM Mono (data), Figtree (UI). Reuse tokens in new UI.
- Website (`website/index.html`) landing page is not yet re-themed to dark —
  only the two desktop dashboards + manifest were converted.
- Engine/limits logic stays pure (no I/O) so it is unit-testable; I/O belongs
  in sampler/server/store.
- All timestamps are unix seconds aligned to minute buckets (`ts % 60 == 0`);
  server validates this on ingest.
- API JSON uses camelCase (`pairingToken`, `activeSecs`); SQL and Python use
  snake_case. Extension payload keys: `domain`/`activeSecs`/`bucketTs`;
  android payload: `key`/`active_secs`/`bucket_ts` (legacy mismatch — keep).
- Security invariant: local loopback requests need no token; any request with
  forwarding headers (tunnel) must carry `x-focuslens-token` on non-public
  paths. Never weaken `_guard_remote` in server.py; test_server.py locks it.
- Mobile uses npm + package-lock.json; the pnpm workspace must not include it.
